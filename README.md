# Ход строительства — ГК «Семейный трест»

Автоматическая обработка фотографий через **Яндекс Диск (OAuth app_folder) → GitHub Actions → GitHub Pages**. Timeweb не используется.

## Один раз настроить владельцу

1. GitHub → **Settings → Secrets and variables → Actions → New repository secret**. Имя: `YANDEX_DISK_TOKEN`; значение — ваш OAuth-токен Яндекс Диска с `cloud_api:disk.app_folder`. Никогда не присылайте токен в чат и не добавляйте его в файлы репозитория.
2. GitHub → **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. GitHub → **Actions → Construction photo progress → Run workflow**. Результат проверяйте во вкладке Actions. До добавления секрета реальное подключение к Яндекс Диску не работает.
4. После успешного запуска будет доступен JSON: https://trestfam.github.io/construction-progress/atmosfera.json . Для других ЖК: `sem-vershin.json` и `feniks.json`.

## Структура папок Яндекс Диска

Путь `app:/` — **корень существующей папки OAuth-приложения «Ход строительства»** (Яндекс Диск → Приложения → Ход строительства). Вторую папку «Ход строительства» создавать не нужно. Ранняя версия скрипта ошибочно создала вложенную папку с таким же названием; её необходимо проверить на наличие файлов и при отсутствии нужных данных удалить вручную. Скрипт больше не использует вложенную папку и не удаляет из неё данные автоматически.

```text
Ход строительства/
  Атмосфера/
    Исходные фотографии/
      Литер 1/
        Октябрь 2026/
          IMG_001.jpg
          IMG_002.jpg
          _READY.txt
      Литер 2/
      ... Литер 8/
    Готовые фотографии/
      Атмосфера. Литер 1. Октябрь 2026/
        <код>-site.jpg
        <код>-eis.jpg
        _manifest.json
  Семь Вершин/
    Исходные фотографии/
      <созданный сотрудником корпус или литер>/
    Готовые фотографии/
  Феникс/
    Исходные фотографии/
      Секция А/
      ... Секция Д/
    Готовые фотографии/
```

Базовые папки и папка текущего месяца для каждого литера/секции создаются автоматически при успешном запуске, даже до 27-го числа. Обработка фотографий текущего месяца по-прежнему начинается только 27-го. Новые секции или литеры внутри `Исходные фотографии` определяются автоматически. Для нового ЖК добавить запись в `config/projects.json`.

## Что делает сотрудник

Загружает фото в папку месяца вида `Октябрь 2026` (ранее созданный формат `ГГГГ-ММ` тоже поддерживается), дожидается **полного окончания загрузки всех снимков** и создаёт пустой текстовый файл `_READY.txt` **последним**. Без этой отметки обработка не начнётся.

Запуск ежедневный, примерно в 10:17 по Уфе. До **27-го** числа текущий месяц не обрабатывается. Если октябрьские снимки загрузили 1 ноября в `Октябрь 2026`, они получат подпись **ОКТЯБРЬ 2026**. Каждый литер обрабатывается отдельно. После успешной обработки создаётся `_manifest.json` — маркер закрытия конкретного литера за конкретный месяц. Следующие запуски его пропускают. При сбое до создания маркера будет безопасная повторная попытка с перезаписью файлов тех же имён.

Исходные снимки **не перезаписываются и не удаляются**. В готовой папке `*-site.jpg` — вариант с текстовой подписью для сайта; `*-eis.jpg` — вариант без подписи для проверки и самостоятельной загрузки сотрудником в ЕИСЖС. Соответствие действующим требованиям ЕИСЖС необходимо проверить отдельно: отсутствие надписи само по себе не гарантирует соответствия.

## Публикация галерей

Публичные адреса изображений и JSON публикуются **через GitHub Pages** по устойчивым путям `https://trestfam.github.io/construction-progress/...`, а не по временным ссылкам Яндекс Диска. Фотографии в Git-коммиты не добавляются. GitHub Pages пересобирает актуальные архивы с Диска при каждом запуске.

Для существующего блока T123 `id="at-hod"` подготовлен `tilda/t123.html`. Его код нужно **один раз** вставить в уже существующий T123, после проверки опубликованного JSON. Это резервная реализация карусели, а **не точная копия дизайна действующего блока**; чтобы сохранить пиксель-в-пиксель существующие стили, потребуется исходный код текущего T123. Код не меняет Tilda автоматически.

## Ограничения и безопасность

- Cron GitHub Actions не гарантирует точное время и может задерживаться или пропускаться; в публичных репозиториях плановые задания иногда отключаются после длительной неактивности.
- Изображения доступны публично всем посетителям GitHub Pages. Токен Яндекс Диска используется только во время Actions.
- Для предотвращения превышения размера Pages установлен внутренний предел **750 МБ изображений**. После его достижения публикация остановится: для большого долгосрочного фотоархива понадобится отдельное публичное объектное хранилище.
- Проверка живой интеграции требует добавления `YANDEX_DISK_TOKEN`; без секрета нельзя подтверждать работоспособность обработки на настоящем Яндекс Диске.
- Для корректировки закрытого месяца администратор может удалить соответствующий `_manifest.json` в готовой папке — это возобновит обработку этого месяца. Делать это нужно осознанно, после обновления исходных фото.

Неизвестные даты не назначать автоматически.
